# Top Music Production

Статический сайт на GitHub Pages: https://topmusic.studio/

Этот репозиторий обслуживает домен. Сайт автоматически синхронизируется из ветки `main` репозитория [`andraw18/gavrishevskiy`](https://github.com/andraw18/gavrishevskiy) каждые пять минут; запуск вручную доступен в **Actions → Sync site from main repository → Run workflow**. После синхронизации workflow отдельно запускает сборку GitHub Pages. Файлы `CNAME`, `.nojekyll`, этот README и сам workflow сохраняются здесь. Изменения страниц нужно вносить в исходный репозиторий — прямые правки опубликованной копии могут быть перезаписаны.

## Админка

Адрес: https://topmusic.studio/admin.html

Старая версия админки хранила изменения в `localStorage` только одного браузера. После первой синхронизации админка публикует правки в ветку `main` исходного репозитория `andraw18/gavrishevskiy`; workflow переносит их сюда, затем GitHub Pages обновляет сайт. Обычный пароль внутри статической страницы не защищает публикацию, поэтому вход проверяет GitHub.

1. Владелец исходного репозитория даёт клиенту доступ на запись к `andraw18/gavrishevskiy` через GitHub Collaborators. Не передавайте клиенту токен владельца.
2. Клиент создаёт токен GitHub со сроком действия. Для владельца репозитория подойдёт **fine-grained personal access token** для одного репозитория с разрешением **Contents → Read and write**. Для приглашённого соавтора личного репозитория GitHub пока не поддерживает такой токен: нужен **personal access token (classic)** с областью **public_repo**. Этот токен имеет более широкие права на публичные репозитории, доступные аккаунту клиента, поэтому его нельзя передавать другим людям; после работы его можно отозвать в настройках GitHub.
3. Клиент открывает админку, вставляет свой токен и нажимает «Войти». Токен хранится только в памяти открытой вкладки и не записывается в исходный код или локальное хранилище.
4. Во вкладке «Страницы» можно менять видимые тексты, адреса ссылок, изображения и видео на главной, лейбле, продакшне и студии. Поля сгруппированы по разделам и доступны через поиск. После редактирования нажмите «Опубликовать».
5. Во вкладке «Услуги» можно менять подробные тексты попапов. Названия, цены и краткие описания услуг редактируются во вкладке «Страницы».
6. Во вкладке «Артисты» можно менять имя, ссылку и фото артистов в восьми сменяющихся карточках; порядок внутри каждой карточки влияет на время показа. После редактирования нажмите «Опубликовать».
7. Во вкладке «Файлы» можно загрузить JPG, PNG, WebP, GIF, MP4, WebM, MP3, M4A, WAV или PDF до 50 МБ и получить ссылку. В полях медиа файл можно загрузить сразу и затем опубликовать обновлённую страницу. Файлы попадают в `assets/media/uploads/`.

Перед переходом на другую страницу админка предупреждает о несохранённых правках. Если кто-то параллельно изменил тот же файл, публикация остановится: перезагрузите его и повторите правку. Обновление GitHub Pages может занять несколько минут.

Админка редактирует текстовые фрагменты, ссылки и атрибуты медиа существующей разметки. Она не перестраивает дизайн.

## Локальный запуск

```sh
python3 -m http.server 8765
```

Откройте http://localhost:8765/. Публикация из админки даже на локальном адресе отправляет изменения в `andraw18/gavrishevskiy` `main`.
